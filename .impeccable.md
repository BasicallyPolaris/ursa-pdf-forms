## Design Context

### Users
Office workers and administrators who need to make existing PDF documents fillable. They are not designers or developers — they want a straightforward tool to place form fields (text inputs, checkboxes, radio buttons) onto PDFs and export them as fillable forms. Their context is task-driven: open a PDF, place fields quickly, export, and move on. They value speed, clarity, and reliability over advanced features.

### Brand Personality
**Clean, precise, professional.** The tool should feel like a well-made instrument — minimal, purposeful, and trustworthy. No unnecessary decoration. The interface should communicate that the output will be correct and professional-grade.

**Voice & tone**: Direct, helpful, unassuming. Labels and messages should use plain language. No jargon, no playfulness, no marketing language.

**Emotional goals**: Efficiency and speed above all. The user should feel in control, confident that their field placements are exact, and focused on the task without distraction.

### Aesthetic Direction

**Visual tone**: Dark, minimal, canvas-focused. The interface should recede and let the PDF document be the star. Toolbars and panels are compact and information-dense without feeling cluttered.

**References**:
- Figma and similar design tools: canvas-based editing, precise snap guides, compact property panels, keyboard shortcuts, minimal chrome
- Modern dark-mode productivity apps: neutral backgrounds, subtle borders, restrained color

**Anti-references**:
- Cluttered enterprise software: avoid dense ribbons, nested menus, modal-heavy workflows, visual noise
- Old-school PDF tools: avoid skeuomorphic UI, dated aesthetics, Windows 95-era form builders
- Generic SaaS dashboards: avoid card grids, marketing chrome, template aesthetics

**Theme**: Dark mode only (enforced via `.dark` class). Light mode is not a current consideration.

**Typography**: Geist Variable (already in use). Clean, modern sans-serif. Small sizes for UI chrome (text-xs = 12px for labels, text-sm = 14px for headings), monospace for numeric values.

**Color palette**:
- Neutral base (oklch, no hue) for backgrounds, borders, and text — already established via shadcn/ui neutral theme
- Semantic accent colors for element types (already in use):
  - Blue: text input fields
  - Green: checkboxes
  - Purple: radio buttons
  - Amber: multiline text areas
- Destructive red for errors/delete (already in shadcn tokens)
- Cyan (#22d3ee) for ruler guides, orange (#f97316) for snap guide lines (already in use)

### Design Principles

1. **Canvas first**: The PDF document dominates the viewport. UI chrome (toolbars, sidebars, panels) should be compact and collapsible, never competing for attention with the document.

2. **Efficient interactions**: Every common action should take the fewest possible steps. Prefer direct manipulation (click to place, drag to move, click to select) over multi-step workflows. Keyboard shortcuts should be discoverable and consistent.

3. **Precision without complexity**: Provide exact positioning (snap guides, grid, numeric inputs) without requiring users to understand PDF coordinate systems. Precision features should be optional and unobtrusive.

4. **Calm restraint**: Use color sparingly — primarily for semantic element-type coding. Avoid gradients, shadows, animations, and decorative elements. The interface should feel quiet and purposeful.

5. **Accessible by default**: WCAG AA contrast ratios on all text and interactive elements. All actions achievable via keyboard. Focus states must be clearly visible. Touch-action: manipulation already enabled.
