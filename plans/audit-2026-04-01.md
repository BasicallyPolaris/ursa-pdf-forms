## P1 Issues (fix before release)

### P1-1: Low-contrast functional text (WCAG AA failure)

**Files**: `src/components/properties-panel.tsx:94`, `src/components/status-bar.tsx:37,42`, `src/components/ui/empty-state.tsx:24,29`

**Problem**: `text-muted-foreground` is further dimmed with opacity modifiers (`/50`, `/60`, `/70`), producing contrast ratios well below 4.5:1 against `bg-card` in dark mode. Full `text-muted-foreground` (oklch 0.708) is ~6.2:1 which passes, but:
- `text-muted-foreground/60` ≈ 3.4:1 — used in SectionHeader (properties-panel.tsx:94)
- `text-muted-foreground/50` ≈ 2.8:1 — used in status bar hints (status-bar.tsx:42), empty state description (empty-state.tsx:29)
- `text-muted-foreground/70` ≈ 4.0:1 — used in empty state title (empty-state.tsx:24)

**Fix**: Remove opacity modifiers on `text-muted-foreground` for functional text. Use the token at full opacity. If lighter text is needed, create a dedicated `--text-secondary` token at a tested contrast ratio. Specific locations:
- `properties-panel.tsx:94` — change `text-muted-foreground/60` to `text-muted-foreground` (or a new tested token)
- `status-bar.tsx:37` — change `text-muted-foreground/60` to `text-muted-foreground`
- `status-bar.tsx:42` — change `text-muted-foreground/50` to `text-muted-foreground`
- `empty-state.tsx:24` — change `text-muted-foreground/70` to `text-muted-foreground`
- `empty-state.tsx:29` — change `text-muted-foreground/50` to `text-muted-foreground`

**Suggested command**: `/harden`

### P1-2: Properties panel multi-select header overflows in German

**File**: `src/components/properties-panel.tsx:862-875`

**Problem**: When multiple checkboxes are selected in German, the header shows:
```
[icon] 2 Ausgewählt Kontrollkästchen
```
In the 212px panel, "2" sits on one line and "Ausgewählt Kontrollkästchen" wraps awkwardly below it. The layout is:
```tsx
<div className="mb-3 flex items-center gap-2">
  {config && <span className="flex h-5 w-5 ...">...</span>}
  <div>
    <span className="text-xs font-medium text-foreground">
      {t("properties.selected", { count: selectedIds.size })}  // "2 ausgewählt"
    </span>
    <span className="ml-2 text-[10px] text-muted-foreground">
      {singleType ? { ... }[singleType] : t("properties.mixedTypes")}  // "Kontrollkästchen"
    </span>
  </div>
</div>
```

The inner `<div>` has no width constraint or flex-wrap, so the two inline spans just overflow/wrap.

**Fix**: Restructure to a two-line layout or use `flex-wrap` with truncation:
```tsx
<div className="mb-3 flex items-center gap-2">
  {config && <span className="...">...</span>}
  <div className="min-w-0">
    <span className="block truncate text-xs font-medium text-foreground">
      {t("properties.selected", { count: selectedIds.size })}
    </span>
    <span className="block truncate text-[10px] text-muted-foreground">
      {typeLabel}
    </span>
  </div>
</div>
```

**Suggested command**: `/arrange`

**File**: `src/components/properties-panel.tsx:705-741` (`SizingButtons` component)

**Problem**: The 4 sizing buttons use only `Expand`/`Shrink` icons with a `rotate-90` to differentiate width from height. Users cannot tell which is width vs height without hovering and reading tooltips. All 4 buttons are in a single row:

```tsx

  <ToolButton onClick={() => matchElementSize("widthWidest")} ...>
    <Expand className="h-3.5 w-3.5" />
  </ToolButton>
  <ToolButton onClick={() => matchElementSize("widthNarrowest")} ...>
    <Shrink className="h-3.5 w-3.5" />

  <ToolButton onClick={() => matchElementSize("heightTallest")} ...>

  </ToolButton>
  <ToolButton onClick={() => matchElementSize("heightShortest")} ...>
    <Shrink className="h-3.5 w-3.5 rotate-90" />
```

### P1-4: Centering section precedes element identity for single elements

**File**: `src/components/properties-panel.tsx:933-935`

**Problem**: When a single element is selected, the panel order is:
1. Element type header (e.g. "Text Field")
2. **CenterOnPageButtons** (positioning action)
3. **Name, properties, position fields** (identity and configuration)

Users expect to see and edit the element's identity (name, type-specific properties like font size) before positioning it. For multi-select the current order (position → alignment → type properties) makes sense since name isn't editable for multiple.

Current code at line 933-939:
```tsx
<Separator className="mb-3" />
<CenterOnPageButtons />
<Separator className="my-3" />
{isTextField(element) && <TextFieldProperties elementId={element.id} />}
{isCheckbox(element) && <CheckboxProperties elementId={element.id} />}
{isRadioButton(element) && <RadioButtonProperties elementId={element.id} />}
```

**Fix**: Move type-specific properties before centering:
```tsx
<Separator className="mb-3" />
{isTextField(element) && <TextFieldProperties elementId={element.id} />}
{isCheckbox(element) && <CheckboxProperties elementId={element.id} />}
{isRadioButton(element) && <RadioButtonProperties elementId={element.id} />}
<Separator className="my-3" />
<CenterOnPageButtons />
```

Note: Each type-specific component (TextFieldProperties, CheckboxProperties, RadioButtonProperties) already includes its own position section with X/Y/W/H fields. The CenterOnPageButtons just adds center-on-page actions, which makes more sense after editing properties.

**Suggested command**: `/arrange`

### P2-4: CanvasOverlay re-renders on all store changes

**File**: `src/components/canvas-overlay.tsx:38-51`

**Problem**: Destructures many values from the store at the top level (`useEditorStore()`), meaning it re-renders on ANY store property change.

Current code:
```tsx
const {
  elements, activeTool, zoom, pages, pdfBytes,
  selectedIds, gridSize, guides, previewGuide,
} = useEditorStore();
```

**Fix**: Convert to individual selectors:
```tsx
const elements = useEditorStore((s) => s.elements);
const activeTool = useEditorStore((s) => s.activeTool);
// ... etc
```

This is a large component (1162 lines) so this change should be done carefully to avoid breaking things. Some values may legitimately need to update together.

**Suggested command**: `/optimize`

## Systemic Patterns

1. **Opacity-modified `text-muted-foreground`** — appears in 6+ locations. Every `/50`, `/60`, `/70` usage fails WCAG AA. Solution: create a `--text-secondary` token at a tested ratio, or just use full `text-muted-foreground`.

2. **Fixed-width panels with no overflow handling** — Page sidebar (`w-44`) and properties panel (`calc(11rem + 36px)` = ~212px) are fixed width. German translations are 1.5-2x longer than English. All panel content needs `truncate` or `flex-wrap` strategies.

3. **Icon-only buttons** rely exclusively on tooltips — not accessible to screen readers. All ToolButton instances should have `aria-label`.
